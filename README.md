# BRICKFORM

Upload a photo, write one line, get a LEGO model you could really build: turn it with the mouse, replay
the build layer by layer, read the part list. The building is done inside BrickAgent's environment (real
LDraw parts, collision detection, PyBullet stability checks), driven by Claude Code running in a
container (Opus 5.5, through a LiteLLM proxy).

## Running it

```sh
python3 server.py            # http://127.0.0.1:8787
```

`.env` needs `LITE_LLM_KEY`, `LITE_LLM_URL` and `AGENT_MODEL` — the same ones brickbench-run uses.
Two images must exist first: `brickagent` (the official environment) and `brickagent-claude`
(the same thing plus the Claude Code CLI).

## What one generation does

1. The browser scales the photo down to a 1536px JPEG and posts it with the text to `POST /api/jobs`.
2. The backend renders the prompt with BrickAgent's own template (`scripts/prompt.py`) and appends the
   product's side of the brief: the reference photo is at `/work/reference.jpg`, render as you go, write
   `card.json` at the end, and reply in English.
3. Claude Code runs inside the `brickagent-claude` container. `/work` is the only place it can write, and
   the network is off (WebSearch/WebFetch/curl/wget). Every PNG it writes shows up on the page within
   seconds.
4. When it stops, the container runs the official `verify.py` (part count, collisions, stability) and then
   `container/export_model.py`, which embeds every referenced LDraw part into the MPD and tallies the
   part list.
5. The page loads that self-contained MPD and splits it into build layers by the bottom face of each part.

Asking for a change in the chat ("make the roof red") reuses the same `/work` and the same session
(`claude --continue`).

## Files

### The cover

`web/cover-concept.html` keeps the original Mondrian cover as a standalone visual. The real cover lives in
`web/index.html`, styled by `web/cover.css`. The red "Starting a project", yellow "Your model" and blue
"Model history" bricks jump to the studio, the result and the history; all three push forward when
clicked. Below them sit the usual generation state, 3D viewer, model card and part list.

A black "Showcase" brick leads to the gallery between the cover and the studio. It holds nine static
reference builds: eight picked out of the [BrickBench teaser in BrickAgent's
repository](https://github.com/kulits/BrickAgent/blob/master/docs/images/teaser_mosaic.avif), shown by
positioning the original image so one model fills each tile — that project is MIT licensed, and the text
is in `references/BrickAgent/LICENSE`. The architectural model is Said Sürücü's [Ayasofya custom
model](https://github.com/saidsurucu/lego-hagia-sophia), re-encoded locally as WebP to load faster and
credited under CC BY 4.0 as its project asks. **None of the nine were generated by this site from a user
photo.** Entering the gallery drops the tiles into place in layers; the animation is off when the system
asks for reduced motion.

Once a model loads, the history section records the job ID, name, part count and check result **in this
browser only** — no private photos or MPDs are copied. Opening one checks that the original job is still
on the server, then restores it through the existing `?job=<id>`. The list keeps at most 30 entries; once
browser data is cleared or the server's job files are gone, those entries cannot be restored from it.
A static preview cannot generate anything, so the history section there shows a genuine empty state.

To look at the layout alone, run `python3 -m http.server 8788 --bind 127.0.0.1 --directory web` from the
repository root and open `http://127.0.0.1:8788/`. That static preview has no generation API; real
generation needs `server.py` and the environment above.

| Path | What it does |
| --- | --- |
| `server.py` | The page, the job API, the live SSE transcript |
| `pipeline.py` | Prompt assembly, container calls, event translation, verification and packing |
| `container/export_model.py` | Runs in the container: self-contained MPD + part list |
| `web/index.html` `web/app.js` | The product page: framing, chat, replay, part list |
| `web/classic.js` | The "classic" look: hemisphere plus key light, a hairline seam between parts, layered replay |
| `web/vendor/` | BrickAgent's viewer.js and three.js's LDrawLoader (MIT), plus three.js itself |
| `jobs/<id>/` | One conversation: `work/` (the agent's directory), `packed.mpd`, `manifest.json`, `events.jsonl` |
| `standalone.py` | Packs a finished job into one self-contained HTML file |
| `preview.py` | Exports the empty opening state as a standalone HTML file |

`jobs/demo-knight` is the first model this produced, built with Opus 5.5 on 2026-10-17 (a black knight,
126 parts).

## Known limits

- A model takes ten to fifteen minutes and two or three dollars; the "large set" tier takes longer.
- Scoring (VQA/ELO) is not implemented: it needs a GPU this machine does not have. "Checked" on the page
  means `verify.py` passed.
- The server binds to 127.0.0.1 and has no accounts; anyone who can reach the port sees every job.
